# 三国玩法反馈优化设计

## 背景与问题

当前三国玩法单一：玩家从 AI 给的 3 个选项里选一个，AI 流式生成下一段剧情 + 3 个新选项，循环。玩家与测试反馈（@慕慕城名雪）集中三点：

1. **选择无后果感**：选 A 和选 B 体感差不多，剧情不回扣过往选择，玩家觉得"我的选择不算数"。
2. **AI 逻辑固有**：选项框架固定，受模型瓶颈限制，玩法僵化。
3. **阅读焦虑**：叙事信息量大，需要保证文字可读性，不把阅读负担丢给玩家。

代码现状：
- `service/game/game.go` 维护对话上下文 `msgContextMap`，AI 流式输出按 `---` 分段、按 `&` 切分"剧情 / 摘要"，摘要不展示、仅回灌上下文。
- `service/game/types.go` / `store.go` / `engine.go` 已有一套 `GameState`（智力/体质/家境/快乐）与属性系统，但**未接入三国 WebSocket 路径**，是 `RunGameStep` 旧路径的遗留。
- `config/env.toml` 的 `SystemMsg`/`RespFormat` 定义叙事提示词与输出格式，要求 AI 在可见 markdown 末尾输出 `1./2./3.` 选项。
- `route/game/game.go` 的 `GameWS` 已实现 `&` 切分与流式推送。
- 刚修复的卡顿问题（见 `2026-07-02-game-start-stall-design.md`）确保了单次流式、关闭深度思考、有限超时——本设计不得打破该成果。

## 目标

- 让选择产生**可见且跨轮积累的后果**，消除"选择无后果感"。
- 状态面板**可见但不露具体数值**，选择**之后**才揭示本轮后果方向，避免数值焦虑。
- 身份作为**隐式倾向**驱动选项生成，且随玩家行为演化，打破"AI 逻辑固有"。
- 复用现有 `---` / `&` 切分与流式协议，最小改动，不引入二段调用、不退化首字延迟。
- 任何解析失败都不阻断剧情展示，不把错误抛给玩家。

## 非目标

- 不更换模型供应商或模型名称。
- 不引入存档落库、多周目、成就系统（YAGNI）。
- 不做自由文本输入行动（保留 3 选项固定格式）。
- 不展示任何具体数值给玩家。

## 方案

### §1 状态模型与防爆炸

**4 个固定维度（三国身份通用）：**

| 维度 | 含义 |
|---|---|
| `名望` | 在世间与主公眼中的声名 |
| `人心` | 麾下与百姓对你的归附 |
| `实力` | 兵权、武力、智略的综合可用之力 |
| `机缘` | 运气、人脉、关键关系的积累 |

**防爆炸机制（首要设计原则）：**

1. **有界区间**：每维固定 `0–10`，服务端硬性 clamp，AI 输出多少都不溢出。
2. **定性分层，不显数值**：每维 6 档（约 2 分一档），玩家只看到档位名。例 `名望`：籍籍无名 → 小有名气 → 颇有声名 → 威名渐显 → 名震一方 → 天下知名。其余三维同样配置定性档位表。
3. **增量驱动**：AI 只输出本轮 `state_delta`（通常 ±1，偶发 ±2，越界值被服务端忽略），不持有累计值，避免 AI 自行累加失控。
4. **服务端权威**：`GameState` 存于服务端（复用现有 `store.go` 的 map），面板从服务端派生，AI 漂移不影响真实状态。

**身份初始值**：硬编码于身份列表旁，开局写入 `GameState`。例：魏国谋士 = `名望1 人心0 实力2 机缘1`；黄巾小将 = `名望0 人心1 实力1 机缘0`。所有初始值保证 4 维均在 `0–10`。

### §2 身份倾向注入与选项生成

**身份倾向（Identity Affinity）**：每个身份配一句自然语言倾向描述，注入 system 提示，**不写死选项**。例："蜀国谋士：偏好运筹帷幄、借势借力、保全己方；回避莽撞冲杀。" 同时给每个维度微弱生成倾向（软提示，非硬规则）。

**选项生成约束（写入 system 提示，AI 每轮遵守）：**

1. 每轮固定 3 个选项，沿用数字 1/2/3。
2. 三选项须**风格分化**：一个偏身份倾向、一个偏进取/冒险、一个偏保守/稳妥，给玩家真正的取向选择。
3. **不展示选项后果**：选项文案只描述行动，不带 `+1/-1` 或结果暗示；文案 ≤15 字。
4. 选项文本输出在隐藏 JSON（见 §4），不在可见 markdown 出现，避免重复渲染。

**身份倾向的演化**：开局身份是基线，玩家后续选择移动状态。当某维度跨过阈值（如 `实力` 到 6），服务端在 system 上下文追加一句当前态势提示（"你如今手握兵权，行事更受各方瞩目"），AI 据此调整后续选项。身份倾向不再固定，随玩家行为演化。

**注入位置**：复用 `initSystemPrompt` 模板变量。在 `config/env.toml` 的 `SystemMsg` 增加 `{{.identityAffinity}}` 与 `{{.stateHint}}` 占位，由服务端每轮填充，不新增 prompt 文件。

### §3 选择后揭示流程与 WS 协议

**核心：后果"选完才揭示"。** 本轮后果在前端明确呈现为一段反馈，而非埋进下一段叙事。

**一次选择的完整流程：**

1. 玩家点选项 → 前端发 `{type:"choice", session_id, choice}`（协议不变）。
2. 服务端 `HandleChoiceStream` 将用户选择 + 当前 `GameState` + 身份倾向 + 当前态势提示注入上下文，调用流式。
3. AI 流式输出（沿用 `---` 分段，可见部分格式不变）：
   - `## 四字概括`（本轮选择的即时后果标题）
   - 对话 / 旁白 / 事件（现有格式）
   - `&` 之后的隐藏 JSON：`{state_delta, summary, options}`
4. 服务端在流过程中按 `&` 切分（**复用 `route/game/game.go` 现有 `&` 切分逻辑**）：`&` 之前作为 `content` 帧推送（可见剧情）；`&` 之后累积成完整 JSON，流结束后解析。
5. 流结束，服务端：
   - 解析隐藏 JSON → 叠加 `state_delta` 到 `GameState`（clamp）→ 持久化
   - 派生新的定性面板（§1 分层名）
   - 发送新增 `state` 帧
   - 发送 `end` 帧，前端渲染 3 个新选项（现有 `choicesBuffer` 逻辑不变）

**WS 帧类型总览（新增 1 种，其余不变）：**

| 帧 | 现状 | 改动 |
|---|---|---|
| `session` | 有 | 不变 |
| `content` | 有 | 不变（仍按 `---` 分段） |
| `end` | 有 | 不变 |
| `error` | 有 | 不变 |
| `state` | **新增** | 面板定性描述 + 本轮 delta 方向 |

**`state` 帧结构：**

```json
{
  "type": "state",
  "panel": {"名望":"颇有声名","人心":"初得民望","实力":"可堪一用","机缘":"尚需时运"},
  "delta": {"名望":"+","人心":"0","实力":"-","机缘":"0"}
}
```

- `panel`：4 个定性档位名，玩家常驻可见。
- `delta`：本轮变化方向（`+` / `-` / `0`），仍无具体数值，作为"选完才知道后果"的正反馈。

**面板展示时机**：`state` 帧在 `end` 之前发。前端顶部常驻轻量状态条（4 个定性标签 + 图标），收到 `state` 帧更新；`delta` 用短暂高亮/箭头动画提示"这一手带来了什么"，约 1.5s 后淡出，只留档位。

**可读性保障**：状态条始终只显示 4 个定性词，无数字；`delta` 一闪而过的方向箭头。剧情主体仍是流式打字叙事，选项文案 ≤15 字。

### §4 隐藏 JSON 契约与解析容错

**AI 隐藏部分（`&` 之后）固定 JSON 结构：**

```json
{
  "summary": "本轮一两句话的前情摘要，供后续上下文回灌",
  "state_delta": {"名望": 1, "人心": 0, "实力": -1, "机缘": 0},
  "options": ["选项1文案", "选项2文案", "选项3文案"]
}
```

- `summary`：复用现有"摘要回灌"用途。当前 `UpdateContextWithResponse` 已只回灌 `&` 之后的摘要、不含可见剧情（token 节省式摘要）。新设计改为回灌从 JSON 解析出的 `summary` 文本（而非原始 JSON），保持该行为，让 AI 后续轮次记住前情、实现叙事回扣，同时避免历史堆积 JSON 噪声、省 token。
- `state_delta`：值限定 `{-2,-1,0,1,2}`，服务端忽略越界值（防爆炸第二道闸）。
- `options`：前端拿到后走 `renderChoiceButtons`，不再依赖 `*系统提示*：请选择` 文本匹配，改由 `state`/`end` 帧驱动。

**可见部分不再输出选项文本**：`RespFormat` 相应精简，可见 markdown 结束于 `> 旁白`，选项挪进隐藏 JSON，避免重复渲染与歧义。

**解析容错（沿用 `engine.go:parseAIOutput` 先例，分层降级）：**

1. 无 `&` → 视为纯叙事，`state_delta` 全 0，`options` 留空 → 前端用 `*系统提示*` 旧路径兜底渲染选项（向后兼容）。
2. `&` 后 JSON 解析失败 → 记 warn 日志（不记 error，符合日志规范），`state_delta` 全 0，`options` 兜底为 `["继续"]`。
3. `state_delta` 缺字段 → 该维度按 0；多余字段 → 忽略。
4. `options` 数量 ≠ 3 → 不足补"继续"，多于 3 截断。
5. 任何容错都不阻断本轮剧情展示——剧情永远可见，状态可缺，**不把焦虑丢给玩家**。

## 数据流

```text
玩家点选项
  |
  +-- WS 发送 choice（协议不变）
        |
        +-- 后端注入 GameState + 身份倾向 + 态势提示
              |
              +-- 单次流式调用模型（关闭深度思考、有限超时，沿用卡顿修复）
                    |
                    +-- & 之前 -> content 帧（剧情，可见，按 --- 分段）
                    |
                    +-- & 之后 -> 累积 JSON
                          |
                          +-- 流结束: 解析 -> 叠加 delta(clamp) -> 持久化 GameState
                                |
                                +-- state 帧（定性面板 + delta 方向）
                                |
                                +-- end 帧 -> 前端渲染 3 选项
```

## 组件改动

- `service/game/types.go`：`GameState` 调整为三国 4 维（名望/人心/实力/机缘），保留 `SessionID`/`Summary`，移除旧 `智力/体质/家境/快乐` 依赖（旧 `RunGameStep` 路径若保留则单独定义，避免耦合）。
- `service/game/store.go`：复用现有 map，`CreateNewGame` 接收身份初始值。
- `service/game/game.go`：`HandleChoiceStream` 注入 `GameState` + 身份倾向 + 态势提示；新增 `applyDelta`、`clampState`、`panelFromState`、`stateHintFromState`、`parseHiddenPayload`；`UpdateContextWithResponse` 改为回灌 `summary`。
- `route/game/game.go`：`GameWS` 的 `&` 切分逻辑后接 `parseHiddenPayload`，流结束后发 `state` 帧；`StartGameStream` 同样注入身份初始值与倾向。
- `config/env.toml`：`SystemMsg` 增加 `{{.identityAffinity}}`、`{{.stateHint}}` 占位并补充选项生成约束；`RespFormat` 精简可见部分、移除可见选项。
- 身份初始值与倾向表：硬编码于 `route/game/game.go` 的 `identifyList` 旁或独立表，每条身份配 4 维初始值 + 倾向描述 + 维度生成倾向。
- `resource/static/sanguo.html`：顶部新增常驻状态条；处理 `state` 帧（更新档位 + delta 方向动画）；选项渲染改由 `state`/`end` 帧驱动，保留 `*系统提示*` 兜底。

## 测试

**单元测试（Go，沿用 `game_test.go` 风格）：**

1. `clampState`：delta 叠加后 `0–10` 不溢出，越界 delta 被忽略，覆盖 0 减、10 加边界。
2. `applyDelta`：缺字段按 0、多余字段忽略、非 `{-2..2}` 值忽略。
3. `panelFromState`：状态 → 定性档位映射正确，4 维各 6 档全覆盖。
4. `parseHiddenPayload`：正常 / 无 `&` / JSON 损坏 / options≠3 / delta 越界，各路径符合 §4 容错约定。
5. 身份初始值表：每个身份写入 `GameState` 后 4 维均在 `0–10` 且语义正确。
6. `stateHintFromState`：跨阈值（如 `实力` 5→6）正确追加态势提示。

**前端静态测试（沿用 `audio_guard.test.js` 纯函数思路）：**

- 抽取 `state` 帧处理为纯函数：输入面板+delta → 输出渲染结构，测试方向箭头与档位替换。
- 抽取 `&` 切分与选项兜底逻辑为纯函数测试。

**回归（人工，复用卡顿修复的浏览器验证流程）：**

- 开始游戏 → 收 `session`/`content`/`state`/`end`，剧情流式可见，状态条 4 个定性词，3 个选项出现。
- 连续 5+ 轮选择：状态条档位随 delta 演化、方向箭头闪现后淡出、数值永不外露。
- mock AI 返回无 `&` 或坏 JSON：剧情仍完整展示，状态条不变（delta 全 0），选项兜底为"继续"，无报错弹窗。
- 卡顿回归：确认单次流式、无二段调用，首字延迟不退化。

**不测**：AI 文学质量、具体剧情分支（无法稳定断言）。
